EAZY MOBILE V1 MASTER UI / UX VISUAL CONTEXT FOR MANUS
========================================

PURPOSE

This document converts the two supplied Eazy UI reference boards into an
actionable visual and product prompt for Manus.

The two images are visual references, not disposable inspiration. They
establish the intended visual language, information hierarchy, component
style, screen density, navigation model, branding treatment, and the
overall relationship between Eazy’s social, marketplace, chat, wallet,
AI, translation, profile, and settings experiences.

Reference image A: 1000975966.png

Reference image B: 1000929119.png

IMPLEMENTATION TARGET

The product being built is Eazy Mobile V1.

Technology: - Flutter - Android - iOS

The UI should reproduce the visual direction shown in the references
while connecting every screen to the real Eazy architecture and backend
where functionality exists.

This is a production application. The references are not permission to
create static mock screens, fake transactions, fake products, fake AI
answers, fake translation, or dead buttons.

The visual system and the functional system must meet in the same
implementation.

============================================================ PART 1:
MASTER VISUAL PROMPT FOR MANUS
============================================================

PROMPT A: INTERPRETATION OF THE FIRST REFERENCE BOARD

Study the supplied first Eazy UI reference image as a single cohesive
product system.

Recreate its design language in Flutter rather than copying it as a flat
image.

The visual direction is a premium dark mobile ecosystem built around
Eazy’s identity.

The dominant visual characteristics are:

-   Deep black and near-black backgrounds
-   Dark forest green surfaces
-   Emerald and mint green accents
-   Bright neon-green action controls
-   White primary text
-   Muted gray secondary text
-   Rounded cards and controls
-   Thin subtle borders
-   Soft green atmospheric glow
-   Large rounded corners
-   Minimal visual clutter
-   Strong typography
-   High contrast
-   Dense but controlled information
-   Premium financial-product precision combined with social-product
    warmth
-   Cinematic imagery used selectively
-   Consistent Eazy branding
-   Very little visual noise

The product must feel modern, global, premium, confident, and
technology-forward.

It must NOT look like: - A generic banking template - A generic Flutter
Material app - A generic social-media clone - A collection of unrelated
screens - A template filled with green buttons

The green color is part of the brand language, not decoration.

Use dark surfaces to create hierarchy and reserve the brightest green
for important actions, active navigation, confirmation states,
highlights, and brand moments.

The interface should feel almost black at first glance, with green light
appearing where the user needs direction.

GLOBAL COMPOSITION

Use a mobile-first portrait layout.

The screenshots show tall phone frames with substantial use of vertical
hierarchy.

Every screen should have: 1. A clear top region 2. A dominant content
area 3. A clear primary action where necessary 4. Controlled bottom
navigation when the screen belongs to a primary section 5. Consistent
safe-area handling 6. Consistent spacing 7. Consistent corner radii 8.
Consistent icon sizing

Avoid filling every available pixel.

The interface uses breathing room even when information density is high.

VISUAL DEPTH

Create depth through: - Surface contrast - Subtle borders - Very
restrained shadows - Green glow - Image depth - Layered cards -
Overlapping profile avatars - Bottom sheets - Floating controls

Do not use heavy drop shadows.

Do not use excessive gradients.

Do not make every card glow.

The visual hierarchy should remain readable when the green effects are
removed.

BRAND COLORS

Use the reference as the visual authority for the palette.

Primary direction: - Near-black - Forest black-green - Deep emerald -
Emerald green - Mint green - Bright neon green - White - Cool light
gray - Muted gray

Approximate design tokens can be established around: - Main background:
very dark green-black, close to #04150F - Secondary surface: dark
green-black - Elevated surface: slightly lighter forest green - Primary
action: bright emerald/mint green - Accent glow: saturated green with
low opacity - Primary text: white - Secondary text: cool gray - Disabled
text: darker gray

Do not overfit the exact RGB values from screenshots if doing so damages
accessibility. Preserve the visual relationship and contrast.

TYPOGRAPHY

Typography is clean, modern, and highly legible.

Use: - Strong semibold/bold headings - Medium-weight labels - Regular
body text - Small muted metadata - Numeric emphasis for wallet amounts
and prices

Large amounts such as wallet balances and product prices should be
visually prominent.

Do not use decorative fonts.

Do not use excessive font sizes.

Maintain consistent type hierarchy: - Display / hero - Screen title -
Section title - Body - Label - Caption - Metadata

COMPONENT LANGUAGE

Use one reusable component system.

Buttons: - Rounded - Bright green for primary actions - Dark or outlined
for secondary actions - White text on dark buttons - Dark text on bright
green buttons where contrast is stronger - Consistent height -
Consistent corner radius

Inputs: - Dark surface - Thin border - Rounded corners - Clear
placeholder - White entered text - Optional trailing icon - Green focus
state - Inline validation state

Cards: - Dark elevated surface - Rounded corners - Subtle border -
Controlled padding - No excessive decoration

Chips: - Compact - Rounded - Dark background - Active chip uses green
highlight

Icons: - Simple - Consistent stroke/weight - White or muted gray by
default - Green for active states - No random icon styles

Avatars: - Circular - High quality - Optional green ring for
active/selected stories - Small status indicators where appropriate

Toggles: - Dark track when disabled - Bright green when active - Smooth
state transition

SCREEN 03: CREATE ACCOUNT / AUTHENTICATION ENTRY

The Create Account workflow is intentionally different from the older reference-board registration form.

When the user taps "Get Started", the first account-creation screen must be simple.

Show:
- Eazy branding
- Email OR phone number input
- Clear explanation that a verification code will be sent
- Continue action
- Continue with Google
- Continue with Apple

The user chooses one of these paths:
1. Email
2. Phone number
3. Continue with Google
4. Continue with Apple

For email or phone registration:
- Collect the identifier.
- Send the real verification code.
- Continue to the verification-code screen.
- Do NOT ask for a password yet.
- Do NOT ask for profile fields yet.

Google and Apple:
- Start the real provider authentication flow.
- Use recognizable official provider branding.
- Do not use generic Material icons as fake provider logos.

Visual:
- Dark background
- Dark rounded inputs
- Green focus/accent states
- Clear primary action
- Consistent Eazy typography and spacing
- Minimal cognitive load

SCREEN 03A: EMAIL / PHONE VERIFICATION

After the user submits an email address or phone number, show a dedicated verification screen.

Include:
- Back navigation
- Verification title
- Explanation that the code was sent
- Verification code input
- Verify/Continue CTA
- Resend code
- Countdown/rate-limit state where supported
- Invalid/expired code error state

Verification must be backed by the real authentication system. Never treat a locally entered code as proof of verification.

SCREEN 03B: PROFILE SETUP + PASSWORD

After successful verification, move to Profile Setup.

At the top:
- Large circular profile-picture upload control
- Camera/edit/upload affordance

Then collect:
- First name: required
- Last name: optional
- Username: required and must be checked for availability
- Date of birth: required
- Bio: profile field, optional unless backend requirements make it mandatory
- Password: required

Username:
- Check availability against the real backend.
- Show available/unavailable states clearly.
- Prevent account creation with an unavailable username.

Date of birth:
- Use a proper native date picker.
- Display the selected date clearly.

Password:
- Visibility toggle.
- Live password requirements.

Display these password requirements:
- Minimum character length
- Uppercase letter
- Lowercase letter
- Number
- Special character

Each requirement should visibly change between unsatisfied and satisfied while typing.

Then show:
- Terms and Conditions / Privacy acknowledgement
- Primary "Create Account" CTA

The final Create Account action should only be enabled when all required fields, username availability, password requirements, and required legal acknowledgement are valid.

After successful account creation, do NOT send the user directly to Home. Continue to the Discovery flow.

This screen replaces the old "Tell us about yourself" onboarding destination.

Purpose:
Help the new user discover relevant friends/people and Eazy listings/products.

Discovery can use:
- Contacts, only after explicit permission
- People they may know
- Existing Eazy users
- Relevant products/listings
- Relevant interests/content where supported

Suggested structure:
- Discovery welcome/title
- Suggested friends
- People from contacts, if permission is granted
- Suggested listings/products
- Follow/add/connect actions
- Search or category entry points where useful
- Skip/Done action

Contact permissions:
- Request permission explicitly.
- Explain why contacts are needed.

Recommendations:
- Use real backend/application data where available.

The old profile-onboarding screen is no longer the account-creation entry point. Profile setup happens after verification, and Discovery happens after account creation.

PART 4: AUTHORITATIVE AUTHENTICATION + NEW USER WORKFLOW
============================================================

This workflow is authoritative. It supersedes older authentication and
onboarding descriptions contained in the visual reference boards.

SPLASH
  ↓
WELCOME
  ├── GET STARTED
  │     ↓
  │   EMAIL OR PHONE
  │     ↓
  │   VERIFICATION CODE
  │     ↓
  │   PROFILE SETUP + PASSWORD
  │     ↓
  │   TERMS / CREATE ACCOUNT
  │     ↓
  │   DISCOVERY: FRIENDS + LISTINGS
  │     ↓
  │   HOME
  │
  └── I ALREADY HAVE AN ACCOUNT / LOGIN
        ↓
      EMAIL + PASSWORD
        ├── Remember me
        ├── Forgot password
        ├── Continue with Google
        └── Continue with Apple
        ↓
      HOME

AUTHORITATIVE RULES
-------------------

1. The splash animation completes, then opens Welcome.
2. Welcome's primary CTA is "Get Started".
3. "Get Started" opens Create Account.
4. Create Account begins with email OR phone number.
5. Email/phone registration requires a real verification-code step.
6. Password creation happens after successful verification.
7. Profile setup happens after verification.
8. Profile setup includes:
   - Profile picture
   - First name
   - Optional last name
   - Username with availability check
   - Date of birth
   - Bio
   - Password
   - Terms and Conditions / Privacy acknowledgement
9. Successful account creation leads to Discovery.
10. Discovery can use contacts only after explicit permission.
11. Discovery covers friends/people and listings/products where relevant.
12. Completing or skipping Discovery leads to Home.
13. Existing users use the simpler Sign In flow.
14. Sign In contains:
   - Email
   - Password
   - Remember me
   - Forgot password
   - Sign in
   - Continue with Google
   - Continue with Apple
15. Do not merge Create Account and Sign In into one overloaded form.
16. Do not send existing users through new-user onboarding unnecessarily.
17. OAuth users may require a reduced profile-completion path only for
    Eazy-required fields that the provider does not supply.

AUTHENTICATION EDGE CASES
-------------------------

Handle:
- Invalid email
- Invalid phone number
- Verification code expired
- Incorrect verification code
- Verification resend/rate-limit state
- Network failure
- Email/phone already registered
- Username unavailable
- Username validation failure
- Weak password
- Required terms not accepted
- Google authentication cancelled/failed
- Apple authentication cancelled/failed
- Account creation failure
- Contact permission denied
- No contact matches
- No discovery recommendations
- User skips Discovery
- Session restoration after registration/login

Never trap the user in an onboarding loop.

============================================================ PART 6:
VISUAL SYSTEM DETAILS
============================================================

SURFACES

Use a hierarchy such as:

Level 0: Near-black application background

Level 1: Dark forest surface

Level 2: Slightly elevated card

Level 3: Focused/active surface

Do not make every surface the same black.

The difference between surfaces should be subtle but visible.

BORDERS

Use thin low-opacity borders.

Borders should: - Separate surfaces - Define inputs - Improve scanning

Do not create visible boxes around everything.

CORNER RADII

Use rounded geometry throughout.

Suggested hierarchy: - Small controls: 10-14 px - Inputs: 12-16 px -
Cards: 16-22 px - Large hero cards: 20-28 px - Bottom sheets: 24+ px at
top corners - Buttons: pill or highly rounded

Keep radii consistent.

SPACING

Use a predictable spacing system.

Base unit: 4 or 8 px.

Typical: - 8 px small gap - 12 px control gap - 16 px standard padding -
20-24 px screen padding - 24-32 px section separation

Do not compress everything to fit more content.

IMAGERY

Images are a major part of Eazy’s visual personality.

Use: - High-quality portraits - Product photography - Cinematic
environmental imagery - Strong crop - Rounded corners - Correct aspect
ratios

Never stretch images.

Use intentional cropping.

GLOW

Green glow is used sparingly.

Use it for: - Brand moments - Wallet balance - Success - Active focus -
Hero visuals - Assistant accent

Do not place neon glow behind every component.

ANIMATION

Motion should be: - Fast - Subtle - Functional

Use transitions for: - Navigation - Bottom sheets - Button states -
Loading - Success - Story interactions - Wallet confirmation - Assistant
responses

Avoid excessive animation that makes financial flows feel playful.

============================================================

============================================================ PART 9:

============================================================ PART 10:
PRODUCTION FUNCTIONALITY RULE
============================================================

Every visual screen must correspond to a real feature.

Never create:

-   Fake wallet balance
-   Fake transaction success
-   Fake Paystack confirmation
-   Fake AI response
-   Fake translation
-   Fake order status
-   Fake nearby places
-   Fake social relationships
