## Account-deletion behavior and gaps

The authenticated deletion path is implemented and unit-tested. Database/tombstone work and durable exact-key capture commit first; Storage cleanup and Firebase identity removal run after commit, with retryable `pending`/`failed` state and idempotent tombstones. It blocks unsafe wallet/payment/order/sales states, does not prove deletion from provider logs/backups, and has no public unauthenticated request workflow. See `docs/ACCOUNT_DELETION_VERIFICATION_REPORT.md`.

The final privacy notice and deletion page must state these limits. They must not promise immediate deletion from backups, provider records, financial records, security evidence or other participants’ messages without approved evidence.

## Retention decision protocol

Until Anthony and a qualified reviewer approve the schedule, the implementation team must not insert fixed legal retention periods into public pages. For each category, record the purpose, minimum necessary duration, legal/contractual dependency, deletion trigger, hold exception, backup expiry and approving person/date. Proposed periods are planning options only.
